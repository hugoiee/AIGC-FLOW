# AIGC-FLOW 项目搭建记录

> 搭建日期：2026-08-30 · 状态：骨架完成，全链路已验证通过

---

## 一、原始需求

搭建一个新的 monorepo 项目，使用 pnpm workspaces 进行管理。

- 前端：`apps/client` 使用 Next.js + TSX
- 后端：`apps/server` 使用 Hono.js + TS
- 数据库采用：SQLite 单文件
- UI：shadcn/ui（Tailwind v4）

项目定位（来自 README）：**画布节点工作流，用于调用各种模型进行影视资产创作。**

---

## 二、技术选型

需求里已经钉死的：pnpm workspaces / Next.js / Hono / SQLite / shadcn/ui + Tailwind v4。
下面 5 项是需求没覆盖、但会实质影响目录结构和后续开发方式的决策，逐条记录选择与理由。

| 决策点 | 选择 | 理由 | 被放弃的方案 |
|---|---|---|---|
| SQLite 访问层 | **Drizzle ORM + better-sqlite3** | TS 类型从 schema 直接推导，无代码生成步骤；迁移文件是纯 SQL，可读可审 | Prisma（需要 generate 步骤 + 独立 DSL，对单文件 SQLite 偏重）；raw SQL（没有类型） |
| 前后端类型打通 | **Hono RPC（`hc` + `AppType`）** | monorepo 的最大红利：改后端路由/入参，前端调用点在 typecheck 时直接飘红，不需要维护第二份接口定义 | 手写 fetch + 共享 types（类型靠人肉同步）；OpenAPI 生成（多一个生成步骤） |
| 代码规范工具 | **Biome** | 一个工具搞定 lint + format + import 排序，配置量最小，避免 ESLint / Prettier 互相打架 | ESLint + Prettier（三套工具容易配置冲突） |
| 服务端运行时 | **Node 22 + `@hono/node-server`**（dev 用 `tsx watch`，build 用 `tsup`） | 本机已是 Node 22，不在搭项目当天引入 Bun 这个额外陌生项 | Bun（性能更好，但多一个新运行时要学） |
| 首个页面范围 | **最小链路自检页** | 用一个真实页面验证 client → server → SQLite 全链路，把画布（React Flow）留到功能迭代 | 直接上画布骨架（一开始就叠复杂度，出问题不知道卡在哪层） |

### 版本决策（两个需要单独说明的）

**TypeScript 固定 `5.9.3`，不用 7.0.2。**
npm 上最新已是 7.0.2（重写的原生 Go 编译器），但 drizzle-kit / Next 工具链的适配情况未知。
搭项目当天不适合引入这个不确定项。后续要升级请单独开一次，先跑通 `pnpm typecheck` 和 `pnpm build`。

**shadcn preset 选 `radix-nova`。**
shadcn v4 的 CLI 现在强制选 preset（nova / vega / maia / lyra / mira / luma / sera / rhea），
且底座分 base / radix / aria 三种。选 `--base radix --preset nova`，即 Radix 底座 + Lucide 图标 + Geist 字体，
最接近传统印象里的 shadcn/ui。不满意视觉可以换 preset 重新 init。

### 结构上的三个约定

1. **`packages/shared` 不构建，直接导出 TS 源码**（`exports: { ".": "./src/index.ts" }`）。
   server 侧由 tsup 打包，client 侧由 `transpilePackages` 交给 Next 编译，省掉一层构建步骤。
2. **`apps/server` 通过 `exports: { "./app-type": "./src/app.ts" }` 把路由类型暴露给 client**。
   这是 type-only 引用，编译产物里会被完全擦除，不会把后端代码打进前端 bundle。
3. **SQLite 文件放 `apps/server/data/`**，随 `.gitignore` 一起忽略 `*.db` / `*.db-shm` / `*.db-wal`（WAL 模式会产生后两个）。

## 四、关键实现细节

### 4.1 Hono RPC：路由必须链式挂载

这是整个项目最容易踩的坑，已写进 `CLAUDE.md` 和 `apps/server/src/app.ts` 的注释。

```ts
// apps/server/src/app.ts —— 正确写法
const app = new Hono()
  .use("*", logger())
  .use("/api/*", cors({ origin: corsOrigins, credentials: true }))
  .route("/api/health", healthRoute)
  .route("/api/workflows", workflowsRoute);

export type AppType = typeof app;
```

拆成多条独立语句（`app.route(...); app.route(...)`）会让 `AppType` 退化成空类型，
前端 `hc<AppType>` 的类型推导直接失效——而且**不会报错**，只是所有接口调用悄悄变成 `any`。

前端消费方式，不手写 fetch：

```ts
// apps/client/src/lib/api.ts
import type { AppType } from "@aigc-flow/server/app-type";
import { hc } from "hono/client";
export const api = hc<AppType>(process.env.NEXT_PUBLIC_API_URL ?? "http://localhost:3001");

// 调用处
const res = await api.api.workflows.$post({ json: { name, description } });
const one = await api.api.workflows[":id"].$delete({ param: { id: String(id) } });
```

### 4.2 校验 schema 写在 shared，前后端共用一份

```ts
// packages/shared/src/workflow.ts
export const createWorkflowSchema = z.object({
  name: z.string().min(1).max(100),
  description: z.string().max(500).default(""),
});
```

后端用 `zValidator("json", createWorkflowSchema)` 挂在路由上，校验失败自动返回 400；
前端从同一个包导入类型，不存在两边规则不一致的情况。

### 4.3 数据库

表定义即真相，时间戳用 SQLite 的 `CURRENT_TIMESTAMP` 默认值（存 text，与 shared 里的 `z.string()` 对齐）：

```ts
export const workflows = sqliteTable("workflows", {
  id: integer("id").primaryKey({ autoIncrement: true }),
  name: text("name").notNull(),
  description: text("description").notNull().default(""),
  createdAt: text("created_at").notNull().default(sql`(CURRENT_TIMESTAMP)`),
  updatedAt: text("updated_at").notNull().default(sql`(CURRENT_TIMESTAMP)`),
});
```

连接开了 WAL 和外键：

```ts
sqlite.pragma("journal_mode = WAL");
sqlite.pragma("foreign_keys = ON");
```

**字段改动流程（不要跳步、不要手写 SQL）：**
改 `db/schema.ts` → `pnpm db:generate` → 人工 review `drizzle/*.sql` → `pnpm db:migrate`。

### 4.4 TS 严格度基线

`tsconfig.base.json` 被三个包共同继承：

- `strict` + `noUncheckedIndexedAccess`（数组下标访问强制判空）
- `verbatimModuleSyntax`（类型导入必须显式写 `import type`，Biome 会自动修）
- `noImplicitOverride` / `noFallthroughCasesInSwitch` / `isolatedModules`
- 未使用变量交给 Biome 管（不在 tsc 里重复报，避免同一问题两处噪音）

### 4.5 环境变量

server 侧用 zod 校验，缺失或格式错直接 `process.exit(1)`，不让服务带病启动：

| 文件 | 变量 | 默认值 |
|---|---|---|
| `apps/server/.env` | `PORT` | 3001 |
| | `DATABASE_URL` | `./data/aigc-flow.db` |
| | `CORS_ORIGIN` | `http://localhost:3000`（逗号分隔多个） |
| `apps/client/.env.local` | `NEXT_PUBLIC_API_URL` | `http://localhost:3001` |

两个 `.env.example` 已入库，`.env` / `.env.local` 已 gitignore。

## 七、踩过的坑（复现环境时注意）

### 1. `create-next-app` 会生成嵌套的 `pnpm-workspace.yaml`

在 `apps/` 下跑 `create-next-app`，它会在 `apps/client/` 里放一个自己的 `pnpm-workspace.yaml`。
这个文件会**直接切断 monorepo**——pnpm 会把 `apps/client` 当成独立的 workspace 根。
必须删掉。同时它生成的 `README.md` 也建议删掉，避免和根 README 混淆。

### 2. pnpm 11 把 `onlyBuiltDependencies` 换成了 `allowBuilds`

按旧写法配 `onlyBuiltDependencies`，pnpm 11 会**静默忽略**，导致 better-sqlite3 和 esbuild 的
安装脚本没执行（表现为 `[ERR_PNPM_IGNORED_BUILDS]`）。正确写法是映射而非数组：

```yaml
allowBuilds:
  better-sqlite3: true
  esbuild: true
  "@biomejs/biome": true
  sharp: true
```

改完重跑 `pnpm install`，并用下面这行确认原生模块真的能加载：

```bash
node -e "const D=require('better-sqlite3');console.log(new D(':memory:').prepare('select sqlite_version() v').get())"
```

### 3. Biome 默认不认 Tailwind 的 `@apply`

`globals.css` 里 shadcn 写了 `@apply font-sans`，Biome 会报 "Tailwind-specific syntax is disabled"
并**中止整个文件的格式化**。需要显式开启：

```json
"css": { "parser": { "tailwindDirectives": true }, "formatter": { "enabled": true } }
```

### 4. Biome 2.5 弃用了 `linter.rules.recommended`

改叫 `preset`。写旧字段会一直提示 deprecation。直接跑 `pnpm exec biome migrate --write` 自动改。

### 5. Next 16 的 `LayoutProps<"/">` 依赖生成类型

`create-next-app` 的模板里 `layout.tsx` 用了 `LayoutProps<"/">`，这是 Next 从 `.next/types/`
生成的全局类型。**在没跑过 `next dev` / `next build` 的干净仓库里 `tsc --noEmit` 会直接报
`Cannot find name 'LayoutProps'`**（CI 上尤其容易中招）。已改成显式 `{ children: ReactNode }`，
让 typecheck 不依赖构建产物。

### 6. shadcn v4 的 CLI 强制交互选 preset

`init` 不带 `--preset` 会卡在交互选择上（自动化环境会挂住）。且 `--base-color` 这个旧 flag 已移除。
可用的 preset 名：`nova / vega / maia / lyra / mira / luma / sera / rhea`。本项目用的完整命令：

```bash
pnpm dlx shadcn@4.19.0 init --template next --base radix --preset nova --no-monorepo --css-variables -y
pnpm dlx shadcn@4.19.0 add card input textarea badge separator -y
```

注意它会把 `shadcn` 本身也装成运行时 dependency（`globals.css` 里有 `@import "shadcn/tailwind.css"`），
这是预期行为，别手动删。

## 八、已知缺口 / 下一步

骨架阶段刻意没做的事，避免一开始就叠复杂度：

- **画布与节点编辑**：`@xyflow/react`（React Flow）尚未引入。`workflows` 表目前只有
  名称/描述，节点与连线结构（`nodes` / `edges` 字段或独立表）需要在做画布功能时一并设计。
- **模型调用适配层**：文生图 / 图生视频 / 配乐等各家模型的统一调用抽象还没有。
- **暗色模式切换器**：shadcn 的 CSS 变量已经就位（`.dark` class 变体），但没有主题切换 UI。
- **鉴权 / 多用户**：当前是纯本地单用户，没有登录态。
- **测试**：没有引入测试框架。

后续每个功能按 `coding_new_feat` 五步法推进：需求分析 → 任务拆解 → 逐步实现 → 每步验证 → 集成测试。
